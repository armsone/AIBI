Sanitized Composer Isolation Regression Fixtures

This file is an index only. Each regression scenario below previously lived as one `<div>` section inside a single shared document, which meant a DOM query such as `queryFirst` would resolve against the first matching element across all scenarios rather than the one under test. Each scenario has been split into its own standalone, sanitized HTML document under fixtures/composer-isolation/ so it can be loaded in isolation as its own full-page `document`. Source-only: no execution, DOM evaluation, or screenshot capture has been performed against these files. All content is synthetic placeholder markup; no real prompts, answers, or private content appear anywhere in these fixtures.

Loading / Config Selection Instructions

  1. Load exactly one fixture file at a time as the full-page `document` (e.g. open the file directly in a browser tab, or set it as the page content of a single isolated test context). Do not concatenate or embed multiple fixture files into one page, since this would reintroduce the same cross-scenario query collisions these fixtures were split to avoid.
  2. Select the provider config matching the fixture's provider prefix: packages/providers/aibi-providers.json → providers.gemini.selectors for Gemini-prefixed fixtures, providers.claude.selectors for Claude-prefixed fixtures. Fixtures without a provider prefix (03, 04, 05, 06, 08, 09) are provider-neutral boundary/ambiguity cases. Each of these does not get evaluated against "either provider" loosely; instead each one specifies, in its row below, the exact registry selector it matches (Gemini or Claude, cited verbatim from aibi-providers.json) and/or an explicit fixture-only promptInput/submitButton override where no registry selector matches the fixture's plain markup. Fixture-only overrides are config overrides scoped to that single fixture's evaluation only; they are not proposed changes to aibi-providers.json or the shared runtime.
  3. Resolve promptInput first using the selected config's selectors.promptInput list, then derive composerRoot, attachmentCount, and sendButton from that single document per the shared runtime contract in packages/runtime/aibi-browser-runtime.js.

Fixtures and Expected Outcomes

Each row lists the fixture file, the condition under test, and the expected composerRoot / attachmentCount / sendButton outcome. These are expected outcomes per the runtime contract, not observed execution results.

  • 01-gemini-empty-formless.html — Empty formless Gemini composer, send button absent when empty. Expected: composerRoot = the .composer-container[role="region"] element (safe landmark, not document.body/document.documentElement); attachmentCount = 0; sendButton = null (no candidates in scope).
  • 02-claude-empty-formless.html — Empty formless Claude composer, send button absent when empty. Expected: composerRoot = the fieldset.composer-fieldset[role="group"] element; attachmentCount = 0; sendButton = null.
  • 03-page-root-boundary-orphan.html — Orphan textarea that is a direct child of document.body (no wrapper divs), so input.parentElement = body, input.parentElement.parentElement = html, and input.parentElement.parentElement.parentElement = null — every structural-ancestor candidate the runtime could fall back to is body/html/null, and no form/[data-testid="composer"]/ [class*="composer"]/fieldset,[role="region"],[role="group"] ancestor exists at any depth. promptInput resolution: neither the Gemini nor Claude registry promptInput selectors match a bare <textarea id="orphan-prompt-input">, so this fixture uses an explicit fixture-only override: promptInput = ['#orphan-prompt-input'] (exact id selector, evaluated only for this fixture, not a registry entry). Expected: composerRoot = null (boundary guard rejects body/html/null); attachmentCount = 0; sendButton = null (no root to scope the query against). The page-level #global-nav-submit button must never be selected as a send candidate.
  • 04-history-attachment-exclusion.html — One prior-turn history thumbnail outside the composer, one staged thumbnail inside the active form[data-testid="composer"]. Selectors: promptInput matches the Gemini registry selector textarea[aria-label*='prompt' i] exactly, via <textarea class="prompt-input" aria-label="Prompt input"> (no override needed); composerRoot resolves via input.closest('[data-testid="composer"]') to form.current-composer-form, which structurally excludes the sibling .history-stream thumbnail; attachmentCount is counted via the Claude registry selector div[data-testid='file-thumbnail'], which matches exactly one element scoped inside that form (the history thumbnail is outside the scoped root and is not counted regardless of selector); sendButton matches the shared Gemini/Claude registry selector button[aria-label*='Send' i] against the single [data-testid="send-button"] inside the form. Expected: composerRoot = the form.current-composer-form element; attachmentCount = 1 (history thumbnail excluded by scope); sendButton = that single [data-testid="send-button"]. This count is a structural consequence of DOM scoping to composerRoot, not of any attachment-selector difference between providers.
  • 05-ambiguous-send-candidates.html — Two visible type="submit" buttons inside one composer scope. Selectors: promptInput matches the Gemini registry selector textarea[aria-label*='prompt' i] exactly, via <textarea class="prompt-input" aria-label="Prompt input"> (no override needed); composerRoot resolves via input.closest('[data-testid="composer"]') to form.ambiguous-composer; both buttons (aria-label="Send primary" / "Send secondary") match the shared Gemini/Claude registry selector button[aria-label*='Send' i], yielding 2 candidates. Expected: composerRoot = the form.ambiguous-composer element; attachmentCount = 0; sendButton = null (uniqueness guard rejects 2 registry-matched candidates).
  • 06-filtered-send-candidates.html — Voice and dictation buttons present alongside one legitimate send button in the same composer scope. Selectors: promptInput matches the Gemini registry selector textarea[aria-label*='prompt' i] exactly, via <textarea class="prompt-input" aria-label="Prompt input"> (no override needed); composerRoot resolves via input.closest('[data-testid="composer"]') to form.control-composer. Neither the voice button (aria-label="voice mode") nor the dictation button (aria-label="음성 받아쓰기") matches any Gemini or Claude registry submitButton selector on their own, so this fixture uses an explicit fixture-only override: submitButton = ['.button-group button'] (broad, evaluated only for this fixture), which admits all 3 buttons into the candidate pool so the runtime's negative-label filter (/stop|중지|정지|voice|음성|dictat|받아쓰기/) is what performs the exclusion rather than the selector query itself. The remaining send button (aria-label="보내기") is independently an exact Gemini registry match via button[aria-label*='보내기' i]. Expected: composerRoot = the form.control-composer element; attachmentCount = 0; sendButton = the single [data-testid="send-button"] (voice/dictation filtered out by label, leaving exactly one candidate).
  • 07-claude-attach-and-true-send-typebutton.html — Claude fieldset with an "Attach files" type="button" and a true send type="button" with a paper-plane icon; both match the broad fieldset button[type='button']:not([disabled]) selector. Expected: composerRoot = the fieldset.composer-fieldset[role="group"] element; attachmentCount = 0; sendButton = the single .claude-send-btn (attach button excluded by negative semantic filter, leaving exactly one positive candidate).
  • 08-ambiguous-two-true-send.html — Two distinct buttons, each with an explicit positive send semantic (paper-plane icon + "Send" label) at the same priority level. Expected: composerRoot = the fieldset.composer-fieldset[role="group"] element; attachmentCount = 0; sendButton = null (uniqueness guard rejects 2 positive candidates).
  • 09-unlabeled-unknown-button-no-positives.html — A real Claude fieldset composer containing one visible, non-excluded type="button" with no positive send semantic (no "Send"/"전송" label, no aria-label, no paper-plane icon, no submit type). Selectors: promptInput matches the Claude registry selector fieldset div[contenteditable='true'] exactly, via <fieldset class="composer-fieldset" role="group"> <div class="ProseMirror" contenteditable="true"> (no override needed); composerRoot resolves via input.closest('fieldset,[role="region"],[role="group"]') to the fieldset.composer-fieldset[role="group"] element; the lone button.generic-action-btn matches the Claude registry submitButton selector fieldset button[type='button']:not([disabled]) exactly, so it is admitted into the candidate pool by the selector query itself (this is not a selector-exclusion case). Expected: composerRoot = the fieldset.composer-fieldset[role="group"] element; attachmentCount = 0; sendButton = null, because the runtime's positive-semantic filter rejects the one candidate for having no "Send"/"전송" label, no matching aria-label, and no paper-plane icon — i.e. the rejection happens in the no-positive-semantic branch, not because the candidate pool was empty.
