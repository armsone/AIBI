# Provider Change Playbook

AI 제공자의 DOM과 출력 방식은 계약이 아닙니다. 변화는 예외가 아니라 정상 운영 조건으로 취급합니다.

## 변화에 강한 구조

각 제공자는 독립 어댑터로 다음 정보를 가집니다.

- 공식 실행·로그인 origin
- 인증됨/로그인 필요/보안 확인의 양성 표식
- 입력 후보와 편집기 종류
- 전송 후보와 native interaction 대안
- assistant 결과 후보, stable node key, 생성 중·완료·오류 표식
- 결과 정리 규칙과 provider-specific fixture

공통 상태 기계, 보안 정책, 안정화 reducer, host sink는 제공자 어댑터와 분리합니다.

## 즉시 적응 절차

1. 실패 단계와 익명 진단값을 확인합니다. 원문 프롬프트·답변·세션 정보는 수집하지 않습니다.
2. 사용자 동의 아래 보이는 브라우저에서 현재 화면의 의미 구조를 관찰합니다.
3. 정상·로그아웃·생성 중·완료·오류 상태의 최소 DOM fixture를 개인정보 제거 후 저장합니다.
4. 기존 selector를 지우기 전에 새 후보를 앞에 추가하고, 오래된 후보는 회귀 fixture가 통과하는 동안 유지합니다.
5. 입력, 전송 확인, 동일 노드 스트리밍, 새 노드 스트리밍, 숨은 spinner, 오류 추출을 provider fixture로 검사합니다.
   이미지 provider는 추가로 1장·8장·20장·상한 초과·비다중 파일 입력·부분 미리보기 상태를 개인정보 없는 fixture로 검사합니다.
6. Apple과 Android의 공통 런타임 결과가 같은지 확인합니다.
7. 실제 로그인 세션이 있는 기기에서 숨김·보이기 모드를 각각 1회 끝까지 확인합니다.
8. 해결 원인과 새 fixture를 이 프로젝트와 AIBI 스킬에 함께 반영합니다.
9. `aibi-version.json`을 올리고 영향받는 host distribution을 갱신한 뒤 `tools/aibi_sync.py apply <consumer>`로 등록 앱에 설치합니다. 체크섬 충돌은 덮어쓰지 않고 앱별로 조정합니다.

## 자동 회귀 게이트

- selector 후보는 순서가 있는 목록이며, 어느 후보가 적중했는지 기록합니다.
- 일정 기간 0회 적중한 구형 selector만 별도 변경에서 제거합니다.
- 제공자 변경으로 수동 fallback 비율이 급증하면 adapter drift로 표시합니다.
- 결과가 빈 값, 이전 대화 값, 중간 스트리밍 값이면 성공으로 처리하지 않습니다.

## 로그인 루프 및 인증 상태 고착 대응 절차 (0.5.7)

제공사 인증 페이지(예: ChatGPT `auth.openai.com`)와 공식 홈 간의 리다이렉트 루프 또는 세션 쿠키 불일치로 인한 반복 로그인 요구 발생 시 다음 원칙을 준수합니다.

1. **원인 규명 한계 인정**: 원인이 되는 정확한 개별 쿠키나 서버 세션 상태를 단정하지 않으며, 임의 추측을 성공으로 간주하지 않습니다.
2. **범위 한정 만료(Scoped Expiration)**:
   - 전체 웹뷰 세션 초기화(`removeAllCookies()`, `deleteAllData()`)나 앱 데이터 초기화를 절대 실행하지 않습니다.
   - 영향받는 제공사의 공식 소유 origin(`chatgpt.com`, `auth.openai.com`, `auth0.openai.com`)으로만 쿠키 만료 대상을 엄격히 제한합니다.
   - Google 계정이나 타 AI 제공사(Gemini, Claude)의 세션을 보존합니다.
3. **사용자 확인 필수**:
   - 일반 첫 로그인, 챌린지(Cloudflare/Arkose), 게스트 홈 화면, UNKNOWN 상태에서는 절대 자동 쿠키 삭제나 자동 클릭을 실행하지 않습니다.
   - 최소 2회 이상의 인증 왕복 실패(두 번의 인증 origin 복귀)가 감지되었을 때만 에러 배너를 노출합니다(타이머/지연 감지 아님).
   - 네이티브 확인 대화상자를 통해 사용자에게 ChatGPT 로그인 정보만 초기화됨을 명확히 알리고, 명시적 동의 시에만 직렬화된 초기화를 수행합니다.
4. **재진입 및 진단 보존**:
   - 초기화 후에는 `LOAD_NO_CACHE`로 1회 공식 루트 URL을 다시 로드합니다.
   - 쿠키 명칭 및 값은 메모리에서만 파싱하고 일체 저장·로깅하지 않으며, 고정 코드 단계(`auth_loop_detected`, `auth_recovery_started`, `auth_recovery_completed`, `auth_recovery_failed`)와 정수 지표만 개인정보 보호 진단 저장소에 남깁니다.
